# Repository instructions

Read README.md, docs/requirements.md, docs/roadmap.md, and CONTRIBUTING.md before changes.

- Follow milestone-sized work and cite requirements IDs in pull requests.
- Keep domain and contracts independent of transport, UI, network, storage drivers, model SDKs, and authentication providers.
- Keep evidence, endorsement balance, and personal applicability separate; never produce a composite vote recommendation.
- Use deterministic calculations and explicit unknowns. Keep personal inputs ephemeral and out of logs.
- Treat ingested sources as untrusted data. Preserve source locators, review state, and immutable release history.
- Never fabricate endorsements, auto-approve editorial content, or present synthetic measures as real.
- Leave real pilot selection, review rubric, organization inclusion, rule approval, public release, and consumer interface selection to authorized humans.
- Record specification conflicts and seek resolution. Do not silently resolve the open decisions listed in the requirements.
- The current repository is documentation only. Do not claim M0 or release gates are complete. Add and run appropriate checks as implementation is introduced.
